# Piloto de 90 dias

Roteiro para uma empresa que acaba de entrar na aliança. O objetivo é sair dos 90 dias com resultados medidos em poucos processos, em vez de iniciativas espalhadas sem medição.

## Dias 1 a 30: fundação

**Objetivo:** pessoas, regras e linha de base definidas.

- [ ] Indicar o representante da empresa no comitê da aliança.
- [ ] Escolher um champion por área participante.
- [ ] Publicar internamente a lista de ferramentas de IA aprovadas e a classificação de dados (veja o [modelo de política](politica-de-uso-modelo.md)).
- [ ] Escolher **de dois a três processos-piloto** por área. Bons candidatos:
  - acontecem toda semana;
  - têm resultado fácil de medir (tempo, retrabalho, qualidade);
  - não envolvem decisões de alto impacto sobre pessoas.
- [ ] Registrar a **linha de base** de cada processo antes de mudar qualquer coisa (veja [Indicadores](indicadores.md)).
- [ ] Apresentar o manifesto e o checklist [Antes de enviar](antes-de-enviar.md) para as pessoas envolvidas.

## Dias 31 a 60: pilotos

**Objetivo:** usar IA de forma recorrente nos processos escolhidos.

- [ ] Montar o mapa de tarefas de cada time (veja o [compromisso 1](../compromissos/01-uso-consciente.md)).
- [ ] Documentar os fluxos usados na biblioteca (veja o [compromisso 3](../compromissos/03-produtividade-com-metodo.md)).
- [ ] Encontro semanal de 15 minutos dos champions: o que funcionou, o que não funcionou.
- [ ] Registrar incidentes e erros, sem culpa.

## Dias 61 a 90: medir e compartilhar

**Objetivo:** comparar com a linha de base e levar o aprendizado para a aliança.

- [ ] Medir os mesmos indicadores da linha de base.
- [ ] Classificar cada processo: a IA ajudou, não fez diferença ou atrapalhou.
- [ ] Decidir para cada processo: manter, ajustar ou abandonar.
- [ ] Preparar um caso para o encontro trimestral, incluindo o que não funcionou (veja o [compromisso 8](../compromissos/08-aprender-em-alianca.md)).
- [ ] Contribuir com pelo menos um fluxo para a biblioteca compartilhada.

## Exemplo de processos-piloto para times de dados

| Processo | Indicador de resultado | Linha de base (exemplo) |
|---|---|---|
| Documentar tabelas novas no catálogo | % de tabelas documentadas em até 7 dias | 30% |
| Escrever testes de qualidade de dados para pipelines | Tempo médio para cobrir um pipeline novo | 2 dias |
| Responder pedidos ad hoc de dados | Tempo de ciclo do pedido; pedidos refeitos | 3 dias; 25% |
| Revisar SQL de colegas | Defeitos encontrados depois do merge | 4 por mês |

Os números da tabela são ilustrativos. Use os seus.
